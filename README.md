# TV9 Multi-Platform Publisher — Foundation

This is the starting skeleton from the build guide: FastAPI + PostgreSQL,
running in Docker, with the core data model in place (`social_accounts`,
`posts`, `post_targets`) and a working REST API for creating accounts and
scheduling posts. No platform adapters are wired up yet — that's next.

## Getting Started in VS Code

1. **Open the folder** `tv9-publisher/` in VS Code (`File > Open Folder`).

2. **Install the Docker extension** if you don't have it (VS Code will
   usually prompt you since there's a Dockerfile present).

3. **Create your local .env file:**
   ```bash
   cp .env.example .env
   ```
   You don't need to fill in the platform credentials yet — leave them
   blank for now.

4. **Start everything:**
   ```bash
   docker compose up --build
   ```
   This starts Postgres and the FastAPI app. First run will take a
   minute to build the image.

5. **Run the initial migration** (in a second terminal, while
   `docker compose up` is running in the first):
   ```bash
   docker compose exec api alembic revision --autogenerate -m "initial schema"
   docker compose exec api alembic upgrade head
   ```
   This creates the `social_accounts`, `posts`, and `post_targets`
   tables in Postgres based on `app/models.py`.

6. **Check it's alive:**
   - Health check: http://localhost:8000/health
   - Interactive API docs (auto-generated by FastAPI): http://localhost:8000/docs

## Try it out

From the `/docs` page (or with curl), you can:

1. `POST /accounts/` — register a fake social account to test with, e.g.:
   ```json
   {
     "platform": "youtube",
     "account_name": "TV9 Main Channel",
     "secrets_manager_arn": "placeholder-not-real-yet"
   }
   ```
2. `POST /posts/` — create a post targeting that account:
   ```json
   {
     "title": "Test post",
     "caption": "Testing the pipeline",
     "media_type": "text",
     "created_by": "parth",
     "target_account_ids": ["<the account id from step 1>"],
     "scheduled_for": "2026-07-20T18:00:00Z"
   }
   ```
3. `GET /posts/` — see the post with its `post_targets`, currently sitting
   at `status: pending` — because nothing is actually publishing yet.
   That's the next phase: building the YouTube adapter and the worker
   service that picks these up and calls it.

## Running the Office Demo

This adds a `/demo` mode and a visual dashboard so you can show a
believable end-to-end walkthrough before real platform adapters exist.
**These demo endpoints are not production code** — they simulate
publishing instead of actually calling YouTube/Instagram/etc.

1. Make sure the stack is running and migrated (see steps above), then
   open: **http://localhost:8000/dashboard**

2. In the demo, click the buttons in this order:
   - **"Seed Demo Data"** — creates 4 fake TV9 accounts (YouTube,
     Instagram, Facebook, X) and 3 sample posts, each targeting all
     4 platforms. You'll see them appear as gray "pending" dots.
   - **"Advance Publishing"** — click this once or twice. Each click
     moves pending targets to "publishing" (amber, pulsing), then on
     the next click to "published" (green) or occasionally "failed"
     (red) — simulating what the real worker service will do once
     the platform adapters are built.
   - **"Reset"** — wipes demo data so you can re-run cleanly for a
     second audience.

3. Suggested talking points while demoing:
   - Point at the architecture: "one post, created once, fans out to
     every platform independently — if X fails, YouTube still
     succeeds, and I can retry just the failed one."
   - Mention this is the **foundation only** — the dashboard is
     simulating publishes right now; the next phase replaces the
     simulation with real calls to YouTube, Instagram, Facebook, and X.
   - If asked about timeline: reference the phase plan (AWS
     foundations → adapters → deploy → test → go live).

## What's deliberately NOT here yet

- Platform adapters (`app/adapters/youtube_adapter.py` etc.) — stubbed
  interface only, in `app/adapters/base.py`
- SQS / EventBridge Scheduler integration — this is local-dev only for now
- Secrets Manager — `secrets_manager_arn` is just a string field for now
- Worker service — nothing consumes `post_targets` yet

Each of these maps to a phase in the full build guide. Next up:
the YouTube adapter, since it has the simplest OAuth flow.

## Project structure

```
tv9-publisher/
├── app/
│   ├── main.py            # FastAPI app + health check
│   ├── config.py          # env-based settings
│   ├── database.py        # SQLAlchemy engine/session
│   ├── models.py          # social_accounts, posts, post_targets
│   ├── schemas.py         # Pydantic request/response models
│   ├── routers/
│   │   ├── accounts.py    # POST/GET /accounts
│   │   └── posts.py       # POST/GET /posts (fan-out to post_targets)
│   └── adapters/
│       └── base.py        # interface every platform adapter implements
├── alembic/                # migrations
├── docker-compose.yml       # api + postgres, for local dev
├── Dockerfile
├── requirements.txt
└── .env.example
```
